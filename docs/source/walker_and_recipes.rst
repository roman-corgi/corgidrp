The Walker and Recipe System
=============================

``corgidrp.walker`` is the top-level driver for the pipeline. It reads a list of
raw FITS files, selects an appropriate processing recipe, fills in calibration
file paths from the calibration database (caldb), and executes the recipe
step-by-step. Most users only need to call a single function:

.. code-block:: python

    import corgidrp.walker as walker

    walker.walk_corgidrp(filelist, CPGS_XML_filepath, outputdir)


Public Functions
----------------

- :func:`corgidrp.walker.walk_corgidrp` — the main entry point; combines
  recipe generation and execution in one call.
- :func:`corgidrp.walker.autogen_recipe` — builds and returns a recipe without
  running it, useful for inspection or modification before execution.
- :func:`corgidrp.walker.run_recipe` — executes a pre-built recipe dict or a
  path to a saved recipe JSON file.


Recipe Format (JSON)
--------------------

Recipes are JSON objects. The walker ships with a library of templates in
``corgidrp/recipe_templates/``. When a recipe is generated by ``autogen_recipe``,
``template`` is set to ``false`` and ``inputs``/``outputdir`` are populated.

Top-level fields
~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 20 15 65

   * - Field
     - Type
     - Description
   * - ``name``
     - string
     - Human-readable name for the recipe (e.g. ``"l1_to_l2a_basic"``).
   * - ``template``
     - bool
     - ``true`` in template files; the walker sets it to ``false`` on generated
       recipes to distinguish templates from live recipes.
   * - ``inputs``
     - list[str]
     - Absolute paths to the input FITS files. Empty in templates; populated by
       the walker at generation time.
   * - ``outputdir``
     - string
     - Absolute path to the output directory. Empty in templates; populated by
       the walker.
   * - ``steps``
     - list[object]
     - Ordered list of pipeline steps. See `Step objects`_ below.
   * - ``drpconfig``
     - object *(optional)*
     - Key/value pairs that temporarily override global ``corgidrp`` module
       settings for the duration of this recipe (e.g.
       ``"track_individual_errors": false``). Original values are restored after
       the recipe finishes.
   * - ``process_in_chunks``
     - bool *(optional)*
     - If ``true``, the input filelist is split into chunks of
       ``corgidrp.chunk_size`` frames and processed sequentially. Reduces peak
       memory usage. Default: ``false``.
   * - ``ram_heavy``
     - bool *(optional)*
     - If ``true``, frame data is not loaded into RAM at the start; each step
       reads frames individually from disk. Supersedes ``process_in_chunks``.
       Default: ``false``.

Step objects
~~~~~~~~~~~~

Each entry in the ``steps`` list is a dict with the following fields:

.. list-table::
   :header-rows: 1
   :widths: 20 15 65

   * - Field
     - Type
     - Description
   * - ``name``
     - string
     - **Required.** Must match a key in ``walker.all_steps`` or the special
       value ``"save"``.
   * - ``calibs``
     - object *(optional)*
     - Maps calibration type names to file paths. Use ``"AUTOMATIC"`` to let
       the caldb choose the best file at recipe generation time. Add
       ``",OPTIONAL"`` (e.g. ``"AUTOMATIC,OPTIONAL"``) to skip the step
       gracefully if no matching calibration exists.
   * - ``keywords``
     - object *(optional)*
     - Keyword arguments forwarded to the step function. Values must be
       primitive types (int, float, str, bool, list of primitives).
   * - ``skip``
     - bool *(optional)*
     - If ``true``, the step is skipped entirely. Set automatically when
       ``skip_missing_cal_steps = True`` and a required calibration cannot be
       found.

The special step ``"save"`` writes the current dataset to ``outputdir``. It
accepts two optional keywords:

- ``suffix`` — string appended to each output filename before ``.fits``
  (e.g. ``"dark"`` turns ``frame.fits`` into ``frame_dark.fits``).
- ``ram_heavy_save`` — bool; if ``true``, frames are read from disk one at a
  time during the save. Matches ``ram_heavy`` recipe mode.

Minimal example
~~~~~~~~~~~~~~~

.. code-block:: json

    {
        "name": "l1_to_l2a_basic",
        "template": false,
        "inputs": [
            "/data/raw/frame_001.fits",
            "/data/raw/frame_002.fits"
        ],
        "outputdir": "/data/processed/",
        "drpconfig": {
            "track_individual_errors": false
        },
        "steps": [
            {
                "name": "prescan_biassub",
                "calibs": {
                    "DetectorNoiseMaps": "AUTOMATIC,OPTIONAL"
                },
                "keywords": {
                    "return_full_frame": false,
                    "dataset_copy": false
                }
            },
            {
                "name": "detect_cosmic_rays",
                "calibs": {
                    "DetectorParams": "AUTOMATIC",
                    "KGain": "AUTOMATIC,OPTIONAL"
                }
            },
            {
                "name": "correct_nonlinearity",
                "calibs": {
                    "NonLinearityCalibration": "AUTOMATIC"
                }
            },
            {
                "name": "update_to_l2a"
            },
            {
                "name": "save"
            }
        ]
    }

The full set of recognised step names is defined in ``walker.all_steps``.


Custom and User Templates
-------------------------

You can override any default template by placing a JSON file with the **same
filename** in the user templates directory (``corgidrp.user_templates_dir``,
which defaults to ``~/.corgidrp/recipe_templates/``). The walker checks this
directory first.

By default (``corgidrp.enforce_template_structure = True``), user templates must
contain the same step names in the same order as the corresponding default
template. You can modify ``keywords`` and ``calibs`` freely, but cannot
add, remove, or reorder steps. To lift this restriction:

.. code-block:: python

    import corgidrp
    corgidrp.enforce_template_structure = False

or set the equivalent environment variable before running the pipeline.

You can also pass a completely custom template directly:

.. code-block:: python

    walker.walk_corgidrp(
        filelist,
        CPGS_XML_filepath,
        outputdir,
        template="/path/to/my_custom_recipe.json"
    )


CPGS XML File Structure
-----------------------

The CPGS (Coronagraph Planning and Guidance System) XML file is an
observation specification produced by the Roman mission planning tools. It
accompanies every set of raw frames and encodes the parameters used to plan
the observation.

``corgidrp`` reads only the fields it needs. Currently the walker extracts
satellite spot information from the ``<cpgs_input>`` section, specifically the
``<satellite_spots_command_info>`` element, to configure the ``find_spec_star``
step.

Top-level structure
~~~~~~~~~~~~~~~~~~~

.. code-block:: xml

    <?xml version="1.0" ?>
    <obs_specification>
        <observation_number>...</observation_number>
        <observation_information> ... </observation_information>
        <target_list> ... </target_list>
        <satellite_spots> ... </satellite_spots>
        <visit_list> ... </visit_list>
        <cpgs_input> ... </cpgs_input>
        <cpgs_output> ... </cpgs_output>
    </obs_specification>

Key sections
~~~~~~~~~~~~

``<target_list>``
    One ``<target>`` element per astronomical target (science or reference
    star). Each target carries an identifier, celestial coordinates, proper
    motion, parallax, V-band magnitude, and spectral type.

``<satellite_spots>``
    Defines the satellite spot pairs used for wave-front sensing and flux
    calibration. Each ``<pair>`` element specifies intensity relative to the
    host star, clocking angle on the detector, and radial separation in
    units of λ/D.

    .. code-block:: xml

        <satellite_spots>
            <pair ID="1">
                <intensity>1.00E-04</intensity>
                <clocking_angle>0.00</clocking_angle>   <!-- degrees -->
                <radial_distance>5.00</radial_distance> <!-- lambda/D -->
            </pair>
        </satellite_spots>

``<visit_list>``
    An ordered sequence of ``<cgi_visit>`` elements, one per telescope visit.
    Each visit records:

    - ``<cgi_visit_type>`` — the VISTYPE string (matches the ``VISTYPE`` FITS
      header keyword), e.g. ``CGIVST_TDD_OBS``, ``CGIVST_CAL_DRK``.
    - ``<requested_start_time>`` / ``<requested_end_time>``
    - ``<coronagraph_configuration>`` — e.g. ``NFOV``.
    - ``<cgi_excam>`` — EXCAM detector settings: EM gain, frame time,
      photon-counting flag, number of frames, satellite spot configuration.
    - ``<fixed_target>`` — which target from ``<target_list>`` is observed.

``<cpgs_input>``
    A flat summary of the inputs supplied to the CPGS planning tool. For
    observations that use satellite spots, this section includes a
    ``<satellite_spots_command_info>`` element in the format parsed by
    ``walker._get_satellite_spot_info_from_xml``:

    .. code-block:: xml

        <cpgs_input>
            <satellite_spots_command_info>
                (sep1=6.2, angle1=45.4, fr1=1.7e-6, filt1=3D)
            </satellite_spots_command_info>
        </cpgs_input>

    The walker extracts ``sep1`` (separation in λ/D) and ``angle1`` (position
    angle in degrees) and injects them as keyword arguments into the
    ``find_spec_star`` step when they are not already specified in the recipe.

``<cpgs_output>``
    Scheduling outputs (observation windows, durations, roll angles). Not read
    by ``corgidrp``.


End-to-end Example
------------------

.. code-block:: python

    import glob
    import corgidrp.walker as walker

    # Collect all raw L1 frames from the visit directory
    filelist = sorted(glob.glob("/data/raw/visit_042/*.fits"))

    # Point to the accompanying CPGS observation specification
    cpgs_xml = "/data/raw/visit_042/CPGS_obs_042.xml"

    # Run the full pipeline; template is chosen automatically
    recipe = walker.walk_corgidrp(filelist, cpgs_xml, "/data/processed/visit_042/")

    print("Used recipe:", recipe["name"])
    print("Output steps:", [s["name"] for s in recipe["steps"]])

To inspect the recipe before running it:

.. code-block:: python

    import json
    import corgidrp.walker as walker

    recipe = walker.autogen_recipe(filelist, "/data/processed/visit_042/")
    print(json.dumps(recipe, indent=2))

    # Optionally modify the recipe, then run it
    walker.run_recipe(recipe)
